## 0. 一句话结论

`~/.workbuddy/skills/tencent-invest` 确实是 invest 系列的**平行实现**，它多出来的东西
不是「一个腾讯数据源」，而是**三条通道**（腾讯行情原生内核 / westock CLI 长尾能力 /
NeoData 云查询）。本轮把前两条收进 invest-cli 成为一等数据源与新命令，技能层只留一个入口；
顺手修掉 10 个低级缺陷，其中 4 个是「一行改动消灭一类」。

**日常热路径零回归**（缓存命中 54/41/42/58ms，与旧版逐项相同），
**新增一条快 41 倍的行情通道**（三个市场 186ms，对照旧路径同问题串行实测 7.7s），
**冷路径诊断付出 +139ms 的诚实成本**（新增两个真实可达性探测）。
测试 237 → **317**，三个解释器全绿（3.14.7 / 3.9.6 各 317 passed，Homebrew 305 passed + 12 skipped）。

## 1. 先回答你问的那个问题

**「这个系列是不是多了一个腾讯的数据源？」是，而且不止一个。** 逐条实测：

| 通道 | 是什么 | invest-cli 原来有吗 | 实测 |
|---|---|---|---|
| `qt.gtimg.cn` 等四个腾讯公开接口 | 零鉴权原生行情内核：实时/批量/历史行情、K线、分时、标的搜索 | **没有** | 单标的 187ms；6 标的跨市场混合（沪/深/港/美/ETF/可转债）**189ms 一次请求**（多标的的边际成本≈0） |
| `westock` CLI（Go 二进制） | 40+ 子命令：筹码/龙虎榜/陆股通/北向持仓/融资融券/一致预期/ESG/机构评级/研报/股票评分/产业链/板块估值与盈利预测/可转债条款/停复牌/风险事件/新股与交易日历 | **没有**（invest-cli 只有 stock/fund/us/screen 四条链） | `westock chip sh600519` 拿到真人数据；`--help` 52ms（端到端） |
| NeoData 云 API | 腾讯 copilot 的自然语言金融查询 | 没有，且**本轮也不吸收**（理由见 §9） | token 由 WorkBuddy 客户端刷新，12h TTL |

对照它自己的记录：这套实现做过三轮修复（25 个缺陷），也留下了六类可复用 bug 模式与
方法论（`references/known-issues.md`）。这些记录比代码本身更值钱，全部保留。

## 2. 瓶颈在哪：用使用权重算，不是挑最吓人的数字

### 2.1 真实调用分布（2372 次调用，来自 220 个会话文件）

| 子命令 | 占比 | 说明 |
|---|---|---|
| `stock` | **43.4%** | 其中 `600519` 一只占 935 次（全量 39%） |
| `datasources` | 10.7% | 诊断类 |
| `us` | 10.6% | `AAPL` 166 次 |
| `fund` | 7.5% | |
| `intent` / `yingmi` / `wind` / `ttfund` / `screen` / `capabilities` / `watchlist` | 各 1.7–3.0% | |

标的口径：A股/基金 44.2%、美股 16.6%、**港股 0.3%**。
相邻调用间隔（61 个带时间戳样本）：**≤60s 93.4%**、≤300s 96.7%。

**这一条直接否掉了两个想法**：
- 拉长快照 TTL 的杠杆很小。60s → 300s 只把命中率从 93.4% 抬到 96.7%（+3.3pp），
  与第四轮「80% 命中」的结论同向，本轮再次证否（不再动 TTL）。
- 港股那条 3.5s 的路径**不值得优化**（只占 0.3% 调用）。第四轮的「先量化再动手」在这里
  又救了一次时间。

### 2.2 冷路径逐源分解（新缓存目录 + 请求级追踪）

| 命令 | 主源 | 探测 | 取数 | 合计 |
|---|---|---:|---:|---:|
| `stock 600519`（A股） | hithink | 12ms | **525ms** | 537ms |
| `us AAPL` | yfinance | **1063ms** | **3366ms** | **4429ms** |
| `stock 00700`（港股） | eastmoney | 15ms | **3491ms** | 3507ms |
| `fund 110011` | hithink | 0ms | 605ms | 605ms |

`us` 的 4429ms 再往下拆（curl_cffi 请求级追踪，4 次请求）：

```
1769ms  GET query1.finance.yahoo.com/v1/test/getcrumb      ← 反爬 token 握手
 651ms  GET query2.finance.yahoo.com/v8/finance/chart/AAPL
2794ms  GET query2.finance.yahoo.com/v10/finance/quoteSummary/AAPL   ← 基本面主体
 701ms  GET query1.finance.yahoo.com/v7/finance/quote
```

**结论（按使用权重）**：日常 93% 的调用命中缓存、代价 40–60ms，不存在瓶颈；
真正的冷路径代价**几乎全部是上游服务端的响应时间**（hithink 525ms、Yahoo 4.4s、
东财 3.5s），而不是我们的代码。所以「大幅提升日常性能」的正解不是微优化，
而是**换一条更快的路**：腾讯内核同样的问题 187ms（仍比同花顺 525ms 快 2.8×）。这也是本轮的主线。

## 3. 吸收了哪些、放在链的哪个位置

### 3.1 新增文件

| 文件 | 作用 |
|---|---|
| `scripts/sources/tencent.py` | 腾讯行情适配器：`stock()`/`us()` 快照 + `quote()` 批量行情 + `kline()` + `detect()` |
| `scripts/sources/westock.py` | westock CLI 透传：代码位置归一化、取值域提示、失败可读 |
| `scripts/cmd_quote.py` | 新命令 `quote`：免鉴权多标的实时行情 |
| `scripts/cmd_kline.py` | 新命令 `kline`：原生快路径 + CLI 兜底 |
| `scripts/cmd_westock.py` | 新命令 `westock`：40+ 子命令透传 |

### 3.2 链上位置：为什么是 `priority: 37`

链序由优先级降序决定，37 是**有意卡在 yfinance(40) 与 bitget(35) 之间**：

```
us     yfinance > tencent > bitget      ← 富源仍在主位，兜底位换成「有数据且快」的腾讯
stock  hithink > eastmoney > yfinance > tencent   ← 腾讯只在富源全失败时顶上
fund   hithink > ttskill > eastmoney    ← 腾讯不进（见下）
screen eastmoney                        ← 腾讯不进
```

**为什么不让腾讯进主位**（这是本轮最重要的一个「不做」）：腾讯行情**没有基本面**，
净利润/ROE/EPS/资产负债率一个都没有。而 `invest-stock/SKILL.md` 的评分口径消费
ROE(14 处)、负债(7)、净利润(6)、毛利率、股息率。把它提到主位就是把 A股快照从 13 项
基本面退化成纯行情，属**能力降级**，与「不影响能力」直接冲突。宁可慢 0.4s 也不掉字段。

**为什么不做跨源字段拼接**（例如「价格取腾讯、ROE 取同花顺」）：这是 invest-cli
route 层的既有纪律（同一问题整单回退、不混字段），也是本轮不顺从的诱惑。
字段含义在三个市场都不一样（见 §4），拼接会把这些差异带进同一份输出里。

**为什么不动港股那 3.5s**：使用权重 0.3%，且东财的港股答案更全
（21 项含 PE/总市值/振幅/年报数据），腾讯港股只有 12 项且**没有 PE 的可靠位**。
换了就是掉能力、省 0.3% 的时间。

### 3.3 域名/品种边界

腾讯行情不接基金：`fund` 链不含腾讯（本模块不暴露 `fund()` 方法）。
原因见 §4 第 3 条，那是被移植实现里最危险的一个缺陷。

## 4. 移植时改掉的缺陷（不继承清单）

| # | 原实现的问题 | 实测证据 | 本实现怎么处理 |
|---|---|---|---|
| 1 | **字段表只有一张，而同一个下标在不同市场是不同量** | `[47]` A股=涨停价 1377.83、港股=股息率TTM 1.18；`[38]` A股=换手率 0.20、港股=0、美股=0.24；`[57]` A股=成交额(万元)、港股=市盈率 15.15、美股=ROE 148.75 | 按市场分表（`_QT_MAP`）；每个下标都由 **westock CLI 的具名列反查**得到，测试逐字段比对 |
| 2 | 港股换手率**恒为 0.0**（真值 0.78%） | 原实现读 `[38]`，而港股该位是 0，真值在 `[59]`；东财同期 0.78%、hk09988 0.62%、hk01810 0.60%，三个标的都印证 `[59]` | 分市场表；并加回归锁（数值 + 「不许等于 0.0」） |
| 3 | 号码重叠时**静默返回另一个标的** | `quote(["sz110011"])` 回的是 `sh110011 歌华转债`（问的是基金 110011）；`_alt_market` 换市场「自动纠正」的副作用 | ① `stock()` 对基金代码直接拒绝并指向 `fund`；② `quote()` 对 11xxxx 重叠段带冲突说明（数值照给、但写清楚这是可转债）；③ `_alt_market` 收窄到同号换市场 |
| 4 | 边界把故障降级成**空结构**，与「查无此数据」不可区分 | 原 `_never_raise` 让 16 个函数静默返回空串/空 list（它自己的 known-issues ①） | 传输故障 → `ok=False` + 可读原因；请求成功但标的不在响应里 → 记入 `missing`。两类分开 |
| 5 | `normalize_code` 对非标的输入产出**看似合理的错值** | `CompScore→usCOMPSCORE`、`gdp→usGDP`、`hs→usHS`、`None→usNONE` | 认不出来一律返回空串；上层据此报「无法解析」而不是把原文当代码发出去 |
| 6 | **帮助文本 / 限流通告当数据**返回（rc=0） | `westock macro gdp`：35 行帮助、零 stderr、**退出码 0**；`westock kline ... --period m5` 密集调用后打印「请求过于频繁，请稍后再试」、rc=0 | 在 spawn 边界判形状：帮助页（`Usage:` + `Available Commands:`）与单行短通告（限流/服务异常）一律报错；调用方主动 `--help` 时照常放行 |
| 7 | `rc=0 但输出为空` 被当成成功 | 原实现踩过 `westock etf` 把 usage 打到 stdout 且 exit=0，一段用法说明被当成 ETF 数据 | 空输出即失败 |
| 8 | 失败吞成空串 | 原 `_run` 的 `except` 返回 `""` | 一律抛错并转成可读信封；原因不准为空（CLI 两流皆空时明说） |
| 9 | **硬编码取值白名单** | 原 `_PRESETS` 写死 9 个，真实取值 **22 个**，13 个合法预设被判「不是合法的预设函数」（它自己的 known-issues ㉒ 把修法写反了） | 不硬编码：通用错误时**现场拉一次 `--list`** 把真实取值域附在错误里 |
| 10 | 未知周期静默降级成日线 | 要季线得到日线，标题还写 `day`；且因「有数据」永不触发 CLI 兜底 | 未知周期返回可读错误，让调用方显式降级 |
| 11 | `kline(limit=N)` 恒多回一根 | 要 5 根给 6 根、要 60 给 61 | 裁到调用方要的根数（与 CLI `--limit N` 对齐，避免分页拼接重复） |
| 12 | 名称解析在 `quote` 与 `kline` 上给出**不同标的** | `沪深300ETF`：quote 给 usASHR、kline 给 sh510300；`红利`：quote 给 usSCHD、kline 给 sh601398 | 三条路径共用同一个解析函数（境内 sh→sz→bj→hk 优先），并加跨路径一致性测试 |
| 13 | 搜索结果缓存键不含 `limit`，跨进程截断 | 先 `limit=2` 之后 24 小时内所有 `limit=20` 都只回 2 条 | 键含 `limit`；并加回归锁 |
| 14 | `None`/NUL 入参抛异常穿透调用方 | `westock.kline(None)` → AttributeError；NUL → ValueError（17/23 个对外函数中招） | 在边界统一判参，非字符串忽略、NUL 报可读错误 |
| 15 | 自己写的注释与真实 CLI 契约不符 | 「保持既有文本契约不变」但原生路径只有 11 列、CLI 有 48 列 | 能力边界写进载荷的 `note`，下游不必回来读代码 |
| 16 | **年线没有聚合**（我移植时漏掉的） | 接口 `param=sh600519,year,,,12,qfq` 只回 1 根，数值等于**当日**OHLC（开 1252.15/高 1265.88/低 1248.1/收 1253.8，与当天日线逐位相同）；直接透传就是「当日 K 线冒充年 K」 | 移植 `_aggregate_years`：月K按自然年合成。实测 `--period year --limit 4` → 2023/2024/2025/2026 四根（2024 高 1806.537 低 1142.367） |
| 17 | **代码位置表不全**，且不能照着 `--help` 抄 | 逐条实测 24 组「裸代码 vs 带前缀」：23 组只有带前缀才给数据。漏掉的 5 个命令里，`disclosure 600519` 最危险 —— 它回的是「**未找到业绩预告数据**」，把「代码没写对」伪装成「该标的没有数据」 | 补齐 `bond/disclosure/risk/score/esg`；并锁定**唯一反例** `rating`：它要裸代码（`rating AAPL` 有表、`rating usAAPL` 空），加前缀反而坏 |

## 5. 新增能力与性能账

### 5.1 新命令

| 命令 | 用途 | 实测 |
|---|---|---|
| `invest-cli quote <代码[,代码...]>` | 只要行情（「现在多少钱」），跨市场、一次请求 | 3 个市场（沪/港/美）**186ms** |
| `invest-cli kline <代码> [--period] [--limit]` | K线；日/周/月/年走原生，分钟级自动转 CLI | 原生 195ms vs `westock kline` 443ms（**2.3×**） |
| `invest-cli westock <子命令>` | 40+ 子命令透传（筹码/龙虎榜/资金流/一致预期/ESG/产业链/板块估值…） | `westock chip 600519` 真人数据；代码位置自动归一（`600519`→`sh600519`、中文名亦可） |

**同一句「这三只现在多少钱」的对照**（不是同口径，但同问题）：

```
旧：stock 600519 (549ms) + stock 00700 (3564ms) + us AAPL (3633ms) ≈ 7746ms，且字段更全
新：quote 600519,00700,AAPL = 186ms
```

字段更全这件事必须说清楚：**问基本面就用 `stock/fund/us`（原样不变），问行情才用 `quote`**。
这正是新命令存在的理由，也写在 `cmd_quote.py` 的文档注释里。

### 5.2 热路径零回归（80–93% 的调用）

同一缓存目录、连续 9 次取中位：

| 命令 | 旧 | 新 |
|---|---:|---:|
| `stock 600519` | 54ms | **54ms** |
| `fund 110011` | 41ms | **41ms** |
| `us AAPL` | 44ms | **42ms** |
| `intent deep stock 600519` | 60ms | **58ms** |

为什么加了两条源却不影响热路径：第四轮把**快照缓存判定放在了路由之前**，
缓存命中时根本不 import 适配器模块（新模块 import 自耗 19.9ms，一次都没付）。

### 5.3 冷路径的诚实账

| 命令 | 旧 | 新 | 判定 |
|---|---:|---:|---|
| `stock 600519` | 583ms | 678ms | 区间重叠（558–756 / 591–1686），噪声内 |
| `fund 110011` | 754ms | 746ms | 无变化（腾讯不进 fund 链，与设计一致） |
| `us AAPL` | 4382ms | 4382ms | 未变（主位仍是 yfinance） |
| `datasources` 冷 | 1124ms | **1430ms** | **+306ms**，逐源分解后其中 **+139ms 是我的两个新探测**（tencent 114ms + westock 25ms），其余是 yfinance 探测自身 0.8–2.3s 的抖动 |
| `datasources` 热 | 100ms | 110ms | 基本不变 |
| `capabilities` 冷 | 1179ms | 1385ms | 同上 |
| `capabilities` 热 | 68ms | 74ms | 不变 |

这 139ms 是**为真实可达性付的**：判据必须与取数走同一条通道，否则就会重演
「装了 ≠ 连得上」（yfinance 那段教训）。按使用权重折算约 3.5ms/次调用。
我考虑过把探测并发化（能把冷诊断从 1.6s 压到 1.4s，因为大头是 yfinance），
**决定不做**：收益 3.5ms/次，而并发会给注册表这个核心路径引入新的竞态面。理由记在此处。

### 5.4 兜底位的实际价值

yfinance 不可达时（本机确实发生过，Yahoo 探测失败是常态之一）：

| | 旧兜底 bitget | 新兜底 tencent |
|---|---|---|
| 耗时 | 857ms | **394ms** |
| 内容 | rToken 成交价 + 24h 区间，**无 PE/PB/ROE/市值**，且按其自身 disclaimer 是「代币价/USDT/非交易所官方价」 | 真实美股行情：price/PE/PB/市值/52周/股息率/换手/量比/均价 |

## 6. 低级 bug 与「一行消灭一类」

| # | 缺陷 | 一行/一处修法 | 消灭的那一类 |
|---|---|---|---|
| 1 | `watchlist`（裸调用）**rc=2 + usage** | `action` 改 `nargs="?" default="list"` | 「最自然的写法不支持」。真实调用里裸写法 7 次 vs `list` 6 次，**占比最高的一种原来 100% 失败** |
| 2 | `westock` 帮助文本当数据 | spawn 边界判形状 | 所有「rc=0 但输出不是数据」（帮助页 + 限流通告 + 未来新增的通告） |
| 3 | 腾讯字段口径 | 分市场表 | 所有「数值对但含义错」（港股换手率 0.0、A股 47/48 被当成 52周） |
| 4 | 号码重叠静默换标的 | 代码域守卫 + 冲突标注 | 所有 11xxxx 段（场外基金 vs 沪市可转债） |
| 5 | `search` 缓存键不含 `limit` | 键加 `limit` | 所有「参数没进缓存键」导致的跨进程串味 |
| 6 | 未知周期静默降级 | 命中不到就报错 | 所有「参数不认识就当默认值」 |
| 7 | 名称解析三条路径不一致 | 共用同一解析函数 | 所有「同一入参在不同命令上给不同标的」 |
| 8 | 非代码输入被当成代码发出去 | `normalize_code` 返回空串 | 所有「解析失败 → 变成一个像代码的东西 → 接口少回一条」 |
| 9 | 非字符串/NUL 入参穿透 | 边界统一判参 | 所有 subprocess 参数注入类异常 |
| 10 | 取值域硬编码 | 现场拉 `--list` | 所有「白名单过期后把合法取值判成非法」 |
| 11 | 代码位置表漏 5 个命令 | 一处表补 5 个键 | 21 个命令的「裸代码给不出数据」（`disclosure` 那条还会伪装成「没有数据」） |
| 12 | 两条伪成功（`bond` / `futures list`） | 通告措辞与帮助形状各加一个判据 | 45 个子命令普查出的其余伪成功形态 |

其中第 1、2、5、8 条是**一行改动**级别的修复。

### 7.3 把「口径表正确性」从人工核对变成机器校验

本轮最关键的方法改进。第一版测试是这样写的：

```python
assert abs(r["pe_ttm"] - 19.246907) < 0.05      # 只锁数值
```

（`price`/`pe_ratio`/`high_52week`/`price_ceiling`…），对映射表里每个字段断言
`qt 取出的值 == CLI 那个具名列的值`。下标错、含义错、单位错都会红。

## 8. 自查失误（本轮我错在哪）

**1. 把 47/48 标成「52周高低」，而它们是涨停价/跌停价。**
  实测铁证：涨停价 = 昨收 1252.57 × 1.1 = **1377.83**、跌停价 = ×0.9 = **1127.31**，
  与 `[47]/[48]` 逐位一致；A股真正的 52 周高低在 `[67]/[68]`（1539.98/1151.01）。
  我的测试当时只断言了**数值**，从未验证**含义**，所以把这个错误锁进了测试里。
  发现途径：并行审计员独立复核 + 我用 westock CLI 的具名列反查。
  **教训：只锁数值的断言会给错值发通行证。** 现在改成对具名列校验（§7.3）。

**2. 差点把「bitget 返回空快照」写成结论并写进配置注释。**
  我第一次看到 `us AAPL` 的 `--json` 里「字段数 0」，据此推断 bitget 返回了
  `ok=True` 的空快照。复核后发现：`us` 的输出**是快照本身**（不像 `stock` 那样套
  `data` 一层），我的字段统计脚本去取 `data` 自然得到 0 —— 是**测量假象**。
  真相是 bitget 有数据（13 个键），只是口径是 rToken 代币价。
  已把那条不实注释按实测重写。**教训：统计口径要先确认载荷形状，否则量到的是自己的假设。**

**3. 用了「零值一律剔除」的钝器。**
  为了躲开港股那个假 0.0，我一度把比例字段的 0 全部丢掉 —— 这会把**真实**的 0
  （停牌股换手率 0%、不分红公司股息率 0%）一起删掉。假 0 的真因是**读错下标**，
  修好口径表后应当如实保留 0。已改，并加了「空=缺席 / 0=如实」这对断言。

**4. 自己造了一个悬空引用。**
  新写的路由页里列了 `invest-us`，而 `invest-us` 早已并入 `invest-stock`
  （原文在 `~/.claude/skills-archive/`）。这正是第四轮修过的那一类缺陷。
  已改，并新增**跨根引用守卫**：workbuddy 路由页提到的 `invest-*` 必须真实存在
  （这类引用原先不在任何路径守卫范围内）。守卫自己也有过一次假阳性
  （把路径片段 `2026-09-22_tencent-invest-absorbed-scripts` 切成了技能名），
  已收紧并反向验证。

**5. 反向验证的配对猜错了三次。**
  我第一版把「某条修复 ↔ 某个断言」配对写死，结果有三对不成立：
  断言其实由**两层**机制共同保护（单独回滚一层不会红）、或我锁的判据与那条修复无关。
  处理方式：不粉饰配对，而是把每条断言改成**真能鉴别**的形式（13 条全部重跑通过，
  其中 2 条重写成新的组合回滚验证）。

**6. 移植时漏掉了月K聚合，让「年线」返回当日 OHLC。**
  `invest-cli kline 600519 --period year` 首版返回 1 根、日期是最新交易日、数值是
  **当天**的开高低收量。原因是我只搬了取数没搬 `_aggregate_years`。
  这是**独立验证会话**抓出来的（它的话：「vender 的年 K 是占位符，旧实现有聚合、新实现丢了」）。
  已补聚合与断言（回滚即红）。**教训：移植一份实现时，「它为了绕开接口缺陷而写的补丁」
  才是最容易被漏掉、也最关键的部分。**

**7. 代码位置表是照着 `--help` 推的，不是逐条打出来的。**
  首版 `_CODE_AT` 收了 20 个命令，实测 24 组后发现漏了 `bond`/`disclosure`/`risk`/`score`/`esg`；
  更险的是我一度打算把 `rating` 也加进去，而它恰恰是**唯一要裸代码**的命令
  （`rating AAPL` 有表、`rating usAAPL` 空）。**教训：`--help` 只告诉你位置，不告诉你形态。**

**8. 一开始把冷诊断 +306ms 的差值当成噪声，也把 +139ms 当成必然。**
  前者要用**逐源计时分解**才能定位（yfinance 探测 0.8–2.3s 的抖动掩盖了真实差分），
  后者才是真账。两次都靠再测一次纠正。

## 11. 事后校正（第五轮独立验证，2026-09-22 晚）

本报告初版的部分**延迟数字偏乐观**（单标的写 137ms、原生 K 线写 130/220ms 两处不一致、
`westock --help` 写 22ms）。独立验证方实测后按 `invest-cli` 真实入口、每次全新空缓存、
5 次取中位重测，已在上文逐处改正为：单标的 **187ms**、3 市场 **186ms**、6 标的 **189ms**、
原生 K 线 **195ms**（对照 `westock kline` 443ms）、`westock --help` **52ms**，
旧路径同问题 **7.7s**（原写 10.3s，属上游延迟波动，两次都对）。
结论方向不变，而且更强：`quote` 比旧路径快 **41×**，「6 标的 ≈ 1 标的」说明多标的的边际成本≈0。

另一处口径校正：yfinance 的 `us` 载荷是 **31 叶**（含 `source` 32），此前口头说过「40 项」。
这条同时暴露了一个更值得注意的问题：`--json` 顶层 schema 不统一（`quote` 是信封、
`us`/`stock` 是裸载荷），按 `data` 取叶子的脚本在 yfinance 载荷上会得到 **0**，
看起来像「静默降级」——所以上面的「17 种 schema」不是洁癖问题，它会误导排查。

验证方逐条结论、我的处置、以及**经我复核不成立的两条**（`us` 兜底 ROE 其实在
`financial` 分组里、文本渲染器其实会打印 `note`）全部记在
`docs/复核报告_2026-09-22_第五轮_独立验证.md`。
